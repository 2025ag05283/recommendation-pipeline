1. Objective and data

We built a modular, reproducible pipeline that ingests user, item and interaction data, validates and prepares it, engineers reusable features, trains and evaluates recommenders, and runs end-to-end as an orchestrated DAG. Data source: movielens (MovieLens 100K format: users with age/gender/occupation, movies with release date and 19 genre flags, and explicit 1-5 ratings with timestamps). Raw input: 949 user rows, 1,686 item rows and 100,024 interactions, including 45 documented, deliberately injected data-quality issues (data/raw/injected_issues.csv) that exercise every validation rule.

4. Models

  1. Popularity baseline - ranks unseen items by training popularity; predicts ratings with the Bayesian item average.
  2. Matrix Factorization - r(u,i) = mu + b_u + b_i + p_u . q_i, 40 factors, 30 SGD epochs, learning rate 0.01, L2 0.05; items with < 5 training ratings are not recommended.
  3. Hybrid - z(MF score) + w_content x z(cosine(user genre profile, item genres)) + w_pop x z(log popularity). Weights were grid-searched on the last 10% of the training period (test never used): w_content = 0.5, w_pop = 2.0 (validation NDCG@10 = 0.148).

Coverage = share of the catalogue recommended to at least one user; Diversity = mean pairwise genre dissimilarity (1 - Jaccard) within a top-K list; Novelty = mean -log2(share of users who rated the item). RMSE/MAE are computed on all test ratings for models that predict explicit ratings (popularity predicts the Bayesian item average); the hybrid model is ranking-only.

  • Ranking quality. The best model by NDCG@10 is the hybrid model (NDCG@10 = 0.1572). The hybrid model changes NDCG@10 by +17.2% and Precision@10 by +14.2% relative to the popularity baseline.
  • Matrix factorization alone ranks poorly (NDCG@10 = 0.0818) although it is the most accurate rating predictor (RMSE 1.0232 vs 1.0292 for the baseline). Minimising squared rating error does not optimise top-K ranking: MF promotes items with high predicted ratings that few users actually choose to watch. This is why the hybrid blends the MF score with popularity and genre affinity.
  • Beyond accuracy. Coverage is 4.5% (popularity), 13.9% (MF) and 9.0% (hybrid); diversity is 0.826 / 0.806 / 0.687. The baseline recommends the same few blockbusters to everyone (lowest novelty), while the personalised models trade some of that safety for more varied and novel lists.
  • Cold-start users (no training history) receive popularity recommendations from every model, so their NDCG@10 is identical across models (0.3153).

6. Reproducibility and orchestration

python run_pipeline.py (or python dags/pipeline_flow.py) executes the 10-task Prefect DAG ingest -> validate -> prepare -> transform -> build_features -> train_popularity / train_matrix_factorization -> train_hybrid -> evaluate -> generate_report. All parameters live in configs/config.yaml; seeds are fixed; every stage writes its outputs to a dedicated folder and a JSON summary; each run's status and task durations are written to reports/pipeline_run_summary.json, and all model runs are tracked in MLflow (mlflow ui --backend-store-uri sqlite:///mlflow.db). dags/schedule_pipeline.py deploys the same flow on a daily cron schedule.

7. Limitations and future work

  • Offline, single split: one global time split and offline metrics only; a rolling (multi-window) backtest and online A/B testing would give more reliable estimates.
  • Cold start: new users fall back to popularity; demographic or onboarding-based models could personalise from the first visit.
  • Small, explicit-feedback dataset: MovieLens 100K is small and dense compared with production data; at scale the file-based feature store would be replaced by Feast/a database, and SGD by ALS / implicit-feedback models.
  • Ranking objective: MF optimises rating error, not ranking; a learning-to-rank or BPR objective would align training with the evaluation metrics.
